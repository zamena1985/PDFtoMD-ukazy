# pdf2md-ukazy

Перевод указов Главы Республики Саха (Якутия) из PDF в Markdown. Скрипт читает текстовый
слой PDF и собирает из него Markdown по правилам ТЗ «Перевод PDF-текстов в формат Markdown»:
заголовок, абзацы, пункты и подпункты, таблицы, подписной блок, приложения. Работает на русских
и якутских текстах, без интернета и без нейросетей. Результат это черновик: каждый файл
сверяется с PDF глазами, для этого есть страница проверки.

## Установка

Нужен Python 3.8 или новее.

```
pip install -r requirements.txt
```

Единственная зависимость это PyMuPDF (чтение PDF). После установки интернет не требуется.

## Запуск

PDF лежат в папке с подпапками `ru` и `sah`, имя файла это номер указа: `543.pdf`.

```
python pdf2md.py <папка с PDF> <папка результата> [--indent] [--only ru/543.pdf sah/543.pdf]
```

Пример:

```
python pdf2md.py "D:\указы главы" out --indent
```

В папке результата появятся `ru/543.md`, `sah/543.md` и так далее, а также:

- `report.json`: замечания скрипта по каждому файлу (что проверить глазами);
- `docs.json`: список документов для страницы проверки.

Ключи:

| Ключ | Что делает |
|---|---|
| `--indent` | красная строка у абзацев: в начале абзаца ставится `&emsp;&emsp;` (два широких пробела). Просмотрщик Nextcloud показывает их как отступ. Без ключа абзацы начинаются с края, файл чище |
| `--only ru/543.pdf …` | обработать только перечисленные файлы, отчёт и список документов дополняются, а не перезаписываются |
| `--align` | выравнивание заголовков по центру и блока «Приложение» справа HTML-тегами. Nextcloud такие теги показывает как текст, поэтому для облака ключ не нужен |

## Проверка результата

```
python review.py --pdf <папка с PDF> --md out
```

Откроется страница в браузере: слева PDF, в середине Markdown так, как его увидит читатель,
справа чистый текст для сверки слов. Стрелки ← и → листают документы, клавиша V отмечает
документ проверенным, в поле сверху можно оставить заметку. Отметки хранятся в браузере.
Файлы со значком ✱ в списке это те, по которым у скрипта есть замечания, они показаны жёлтой
строкой под шапкой.

Если есть прежняя версия результата, `--prev <папка>` добавит колонку «Было» со списком
абзацев, которые изменились по тексту.

Проверка нумерации списков (нужен пакет из `requirements-dev.txt`):

```
python check_numbering.py out
```

Markdown берёт номер только у первого пункта списка, остальные считает сам. Скрипт отрисовывает
файлы тем же парсером, что GitHub и Nextcloud, и сообщает, где номер в файле и номер на экране
разошлись. В норме расхождений ноль.

## Что делать с замечаниями в отчёте

| Замечание | Что это и что делать |
|---|---|
| `дефис на границе строки склеен без пробела` | слово с дефисом было перенесено по дефису; скрипт склеил части без пробела (`сирдээҕи-уоттааҕы`). Проверить, что получилось одно слово, а не два |
| `таблица на стр. N: R строк x C столбцов` | найдена таблица с видимыми границами. Сверить число строк и столбцов с PDF |
| `таблица на стр. N продолжается на стр. N+1: части склеены` | таблица была разорвана границей страницы, части склеены, разрезанная строка дописана. Сверить место стыка |
| `… число столбцов разное, склейте вручную` | две части похожи на одну таблицу, но столбцов разное число; скрипт оставил их отдельно |
| `сетка без видимых границ … оставлена текстом` | в PDF была невидимая таблица вёрстки, текст оставлен абзацами. Обычно верно |
| `нумерация: после пункта «2)» идёт «13.»` | внутри пункта начинается другая нумерация (вставляемый текст); она оформлена вложенным списком. Сверить с PDF |
| `подписной блок …` | не удалось собрать таблицу подписи (должность, фамилия, дата, номер). Оформить вручную |
| `ПОЛНОТА: в Markdown N% знаков от исходника` | число знаков заметно отличается от PDF, возможен пропуск или дубль. Пролистать документ целиком |
| `приложение «Структура» это схема из блоков` | организационная схема, в тексте только подписи блоков. Расположение оформляется вручную |
| `НЕТ ТЕКСТОВОГО СЛОЯ` | PDF это скан. Скрипт распознаванием не занимается, нужен OCR |

## Как устроен результат

- Заголовок указа: `# …`. Заголовки приложений после подписи тоже `#`, разделы внутри `##`, пункты вида «1.1» `###`.
- Жирный текст: `**…**`, курсив: `*…*`.
- Пункты «1.» и подпункты «1)» оформлены нумерованными списками, подпункты вложены в пункт. Абзацы, таблицы и вставляемый текст внутри подпункта сдвинуты под него. Нумерация, начинающаяся заново внутри пункта, идёт списком на уровень глубже, иначе читатель увидел бы продолжение чужой нумерации.
- Просмотрщики показывают номера своим стилем: «1.» вместо «1)». Из файла это не управляется.
- Таблицы: Markdown-таблицы, первая строка PDF-таблицы становится шапкой.
- Подписной блок: таблица из двух строк: должность и фамилия, под ними дата и номер.
- Сноска «* - …» экранирована как `\* - …`, иначе звёздочка превращается в маркер списка.
- Шапка бланка (ГЛАВА / УКАЗ / ЫЙААХ / г. Якутск), герб, печать и номера страниц не переносятся.
- Выравнивание по центру и справа Markdown не поддерживает, текст идёт по левому краю.

## Ограничения

- Нужен текстовый слой. Сканы не обрабатываются.
- Правила подобраны по указам Главы РС(Я) 2025–2026 годов (Word → PDF, шрифт Times/PT Astra Serif).
  Документы другой вёрстки могут потребовать подстройки правил в `pdf2md.py`: абзацы определяются
  по отступу первой строки, таблицы по тёмным линиям, подпись по строке «№ номер», где номер
  берётся из имени файла.
- Разметка организационных схем и форм с подчёркиваниями остаётся ручной.
